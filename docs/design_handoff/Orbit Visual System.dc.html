1 — Rationale

The one idea: a token exists so a decision is made once. The palette was already sound, so the work went to the places where the system had no opinion and the markup was improvising — type size, radius, row rhythm, focus on coloured ground.

Six named type steps replace nine hard-coded pixel sizes. 10px folds into 11px (10px is below the size at which this stack stays legible at weight 500); 12.5px and 13.5px fold into 13px. Radius becomes two real values — 4px inside a row, 8px for a surface — and --radius is pinned as the source of truth rather than defined once and ignored.

Focus is the one place the old system genuinely broke: a single accent outline sitting directly on a violet chip or an emerald calendar block is a ring against a colour it was never measured against. The ring now carries a 2px neutral halo underneath it, so its contrast is against --bg-raised everywhere, on every substrate.

The ten category hues keep their names and gain even spacing — the violet/indigo pair was 20° apart and the confusable pairs now differ in lightness as well as hue, so they separate under deuteranopia too. Warm chip fills were the only real failures: amber, orange and lime were sitting between 4.1 and 4.4 against their own fill. Fixed.

Added: --success and --warning. Borrowing amber from the category palette for an alert means a Home-space chip and a warning banner are the same colour, which makes the category colour mean two things. It should mean one.

Left alone: no shadows, no elevation language — surface, sunken and a hairline are the correct and complete vocabulary for a dense app, and shadows would put a soft edge on every one of thousands of rows. Native selects and inputs stay. Priority and status stay as text; they are ordinal, not categorical, and colour would compete with the one thing colour already means here.

Markup changes needed

Everything above lands in one file. Three markup passes are worth the churn; the rest can be adopted whenever a component is next touched, because the old utilities still resolve.

  1. Worth it now — the type scale. Codemod across src/: text-[10px]/text-[11px] → text-2xs, text-[12px]/text-[12.5px] → text-xs, text-[13px]/text-[13.5px] → text-sm, text-[15px] → text-lg, text-[17px] → text-xl. Mechanical, one commit, and it also brings the line-heights with it. 663 sites; only the 50 former 10px ones change size.
  2. Worth it now — SpaceIndicator.tsx and CategoryChip.tsx. Replace the ad-hoc chip styling with className="chip" / "chip chip-plain", keeping the existing inline style colour vars. Two files, and chip geometry stops being copied by hand.
  3. Worth it now — calendar busy blocks. In the calendar block component, give anonymous blocks className="busy" instead of a colour var. One file; it is the only way the "somebody else's time" distinction survives without a colour of its own.
  4. Optional, adopt gradually. .row for dense list rows (replaces py-1.5 gap-2 pairs), .tabular on dates and times, .section-label on the uppercase headings, .locked on encrypted placeholders, .pending on optimistic fields.
  5. Not worth it. Nothing needs to change for the colour, focus, radius or elevation work to land — those are pure CSS.
The rework I'd argue for

Now is the landing page, and the range switch belongs to it. The instinct is to put Today/Week/Month on the calendar, because that is where those words live in every other product. But the calendar is a placement tool — you open it knowing the date. Now is the page that answers a question, and Today/Week/Month is just that question at three grains: what do I need to do today, this week, this month. Same query, same layout, one parameter. Putting the switch on the calendar instead splits one idea across two pages.

Cost: / becomes Now rather than the calendar, and the range state moves into the URL (/?range=week) so it survives reload and can be linked. One route, one query hook.

One query per page, not one per widget. If the backend is doing the work, the front end should ask once: a single summary(range) returning counts, events and due items together. That is what makes the summary strip trustworthy — the number and the list below it cannot disagree, because they came from the same response.

People is a page, not a widget on Now. Location is glanceable but rarely actionable, and putting a live map on the landing page means the first thing the app does every morning is ask for GPS. Keep it one nav step away.

Nav goes to three items. Now · Calendar · People, plus settings. Three is small enough that a dense sidebar is no longer necessary — a top row of three works and gives the content its width back.

5 — Verification
  1. pnpm test — tests/contrast.test.ts must be green with no skipped tokens. Check the count of parsed tokens went up by the six new ones (--success, --warning and their -bgs, --focus-ring, --focus-halo) per theme — a silently-unparsed token is the failure mode this test exists to catch.
  2. pnpm build — confirms Tailwind emits the new text-2xs…text-xl utilities. If a text-* class silently produces nothing, the @theme name is wrong.
  3. pnpm smoke — both colour schemes, every interactive control named. Unchanged by this work; a failure here means markup drift, not palette.
  4. By eye, in both schemes: tab through a task list until focus lands on a space chip and on a calendar event block — the ring must show a neutral gap against both fills. Then open week view with a "busy" block visible: it must read quieter than every real event, with no hover needed.
  5. New surfaces, by eye: on People, check a pin sitting half on water and half on land — the halo is what keeps it readable, so it must not be dropped when the pin component is styled. On Now, tab onto the range switch and confirm selection is still obvious in greyscale (screenshot, desaturate) since none of its three signals is hue.
  6. Regression to watch: the 50 former text-[10px] sites grow by 1px. Scan the sidebar footer and the calendar hour gutter for wrapping.

Assumptions, each cheap to reverse: chip fills got a hair lighter in light mode to buy warm-hue headroom; the two extra status colours are additive and touch nothing existing; a manual theme toggle was not added — if you want one, it means a data-theme attribute on <html>, duplicating the dark block under that selector, and teaching the test's brace-matcher about it — worth doing only alongside a settings surface.
